\section{Judgments}

We work with three mutually defined judgment forms:
\begin{align*}
  &\wf{\Gamma}                  &&\text{$\Gamma$ is a well-formed context}\\
  &\hastype{\Gamma}{M}{A}       &&\text{$M$ has type $A$ in context $\Gamma$}\\
  &\conveq{\Gamma}{M}{N}{A}     &&\text{$M$ and $N$ are definitionally equal at type $A$}
\end{align*}
Contexts are snoc-lists: $\Gamma ::= \cdot \mid \Gamma, x{:}A$.
We write $M\sigma$ for the result of applying a substitution
$\sigma$ to a term~$M$, and $[t]$ for the substitution
$\Gamma \to \Gamma, x{:}A$ extending the identity by~$t$,
so that $B[a]$ means $B(\mathrm{id}, a)$.

\section{Head reduction}

We define single-step head reduction $M \leadsto_1 N$ as the
compatible closure of $\beta$-reduction at the head, extended with
projection reductions for Sigma types:
\begin{mathpar}
  \inferrule[\textsc{HR-Beta}]
    { }
    {\App{(\Lamterm{x{:}A}{M})}{a} \leadsto_1 \substone{M}{a}}
  \and
  \inferrule[\textsc{HR-App}]
    {M \leadsto_1 M'}
    {\App{M}{a} \leadsto_1 \App{M'}{a}}
  \and
  \inferrule[\textsc{HR-Beta-Fst}]
    { }
    {\Fst{\MkPair{M}{N}} \leadsto_1 M}
  \and
  \inferrule[\textsc{HR-Beta-Snd}]
    { }
    {\Snd{\MkPair{M}{N}} \leadsto_1 N}
  \and
  \inferrule[\textsc{HR-Fst}]
    {M \leadsto_1 M'}
    {\Fst{M} \leadsto_1 \Fst{M'}}
  \and
  \inferrule[\textsc{HR-Snd}]
    {M \leadsto_1 M'}
    {\Snd{M} \leadsto_1 \Snd{M'}}
\end{mathpar}

\noindent
We write $M \Red N$ for the reflexive-transitive closure of
$\leadsto_1$.  As in the Pi-only system, the validity relation uses
a wrapper $\mathsf{Red}\;\Gamma\;M\;N\;A$ with phantom context and
type parameters.

\section{Domain model}

We describe the domain-theoretic semantics following Coquand--Huber (2018).
The model interprets types as \emph{codes} (finite elements of a Scott domain)
and terms as elements approximated by these codes.

\subsection{Finite elements}

The set $\FinEl$ of \emph{codes} is defined inductively, together with
a set $\FinFun$ of \emph{finite functions} (finite lists of input-output pairs):
\begin{align*}
  u,v,a &::= \Bot \mid \U \mid \Prop \mid \lambda g \mid \PiC{a}{f}
              \mid \SigmaC{a}{f} \mid (u,v) \\
  g,f,h &::= [] \mid (u,v) :: g
\end{align*}
Here $\Bot$ is the bottom element (no information), $\U$ and $\Prop$ are
the codes for the universe and the propositional universe, $\lambda g$
is a function value with finite graph~$g$, $\PiC{a}{f}$ is a Pi-type code
with domain code~$a$ and codomain function~$f$, $\SigmaC{a}{f}$ is a
Sigma-type code, and $(u,v)$ is a pair code.

\subsection{Evaluation}

The evaluation of a finite function $f$ at input $u$ computes the
\emph{supremum} of all outputs whose keys are below~$u$ in the
information ordering:
\[
  \EvalFun(f, u) = \bigsqcup\{ v_i \mid (u_i, v_i) \in f,\ u_i \leq u \}
\]
The binary supremum $u \sqcup v$ combines compatible elements:
$\Bot \sqcup u = u$, $\U \sqcup \U = \U$,
$(\lambda g) \sqcup (\lambda h) = \lambda(g \mathbin{+\!+} h)$,
$\PiC{a}{f} \sqcup \PiC{b}{g} = \PiC{a \sqcup b}{f \mathbin{+\!+} g}$,
and $u \sqcup v = \Bot$ when $u$ and $v$ have different top-level constructors.

\subsection{Information ordering}

The ordering $u \leq v$ (written $\mathsf{LeCode}\;u\;v$ in the formalisation)
is defined by structural recursion.  On base codes, $\Bot$ is below everything,
$\U \leq \U$, and $\Prop \leq \Prop$.
On compound codes:
\begin{align*}
  \lambda g \leq \lambda h
  &\quad\text{iff}\quad
  \text{for each } (u_i,v_i) \in g,\;\; v_i \leq \EvalFun(h, u_i) \\
  \PiC{a}{f} \leq \PiC{b}{g}
  &\quad\text{iff}\quad
  a \leq b \;\;\text{and}\;\;
  \text{for each } (u_i,v_i) \in f,\;\; v_i \leq \EvalFun(g, u_i)
\end{align*}
Codes with different top-level constructors are incomparable.
The ordering on finite functions uses the \emph{finite condition}:
$g \leq h$ iff for each $(u,v) \in g$, $v \leq \EvalFun(h, u)$.
For coherent functions, this is equivalent to pointwise ordering
$\forall u.\; \EvalFun(g,u) \leq \EvalFun(h,u)$.

\subsection{Coherence}

A finite function $g = [(u_1,v_1), \ldots, (u_n,v_n)]$ represents a
well-defined continuous function only if it is \emph{coherent}: whenever
two keys are \emph{compatible} (have a common upper bound), their values
must also be compatible.  Formally, $\mathsf{Comp}(u,v)$ holds when $u$
and $v$ can be combined via the supremum (same constructor, recursively
compatible), and $\mathsf{CoherentFun}(g)$ requires:
\begin{itemize}
\item each key $u_i$ and value $v_i$ is coherent (recursively),
\item each value $v_i$ is non-$\Bot$,
\item for all $i < j$, if $\mathsf{Comp}(u_i, u_j)$ then
  $\mathsf{Comp}(v_i, v_j)$.
\end{itemize}
On compound elements: $\mathsf{Coherent}(\PiC{a}{f})$ requires
$\mathsf{Coherent}(a)$ and $\mathsf{CoherentFun}(f)$, and similarly for
$\SigmaC{a}{f}$.  Base codes ($\Bot$, $\U$, $\Prop$) are always coherent.

Coherence ensures that the supremum-based evaluation is monotone: if
$u \leq v$ and $g$ is coherent, then $\EvalFun(g, u) \leq \EvalFun(g, v)$.

\subsection{Finite membership}

The predicate $\mathsf{FinMem}(u, a)$ asserts that code $u$ is a valid
\emph{approximation to an element of type~$a$}.  Its key clauses are:
\begin{align*}
  \mathsf{FinMem}(\Bot, a) &= \mathsf{FinMem}(a, \U) \\
  \mathsf{FinMem}(\U, \U) &= \top  \qquad\qquad
  \mathsf{FinMem}(\Prop, \U) = \top \\
  \mathsf{FinMem}(\PiC{a}{f}, \U) &=
    \mathsf{FinMem}(a, \U) \;\wedge\;
    \mathsf{FinMemAllU}(f, a) \;\wedge\;
    \mathsf{CoherentFun}(f) \\
  \mathsf{FinMem}(\lambda g, \PiC{a}{f}) &=
    \mathsf{FinMemFun}(g, a, f) \;\wedge\;
    \mathsf{CoherentFun}(g) \;\wedge\;
    \mathsf{FinMem}(\PiC{a}{f}, \U)
\end{align*}
Here $\mathsf{FinMemFun}(g, a, f)$ requires that for each $(u_i, v_i) \in g$,
$\mathsf{FinMem}(u_i, a)$ and $\mathsf{FinMem}(v_i, \EvalFun(f, u_i))$;
and $\mathsf{FinMemAllU}(f, a)$ requires that each pair in $f$ has its key in~$a$
and its value in~$\U$.  The clause $\mathsf{FinMem}(\Bot, a) = \mathsf{FinMem}(a,\U)$
means that $\Bot$ is a valid approximation in any well-formed type.

\subsection{Key properties}

The following lemmas, all proved in the Agda formalisation without postulates,
are central to the adequacy proof:
\begin{itemize}
\item \textbf{Sup closure:} $\mathsf{FinMem}(u,a)$ and $\mathsf{FinMem}(v,a)$
  imply $\mathsf{FinMem}(u \sqcup v, a)$.
\item \textbf{Coherent evaluation:} If $\mathsf{Coherent}(\lambda f)$ and
  $\mathsf{Coherent}(u)$, then $\mathsf{Coherent}(\EvalFun(f, u))$.
\item \textbf{Monotonicity of FinMem:} If $u \leq v$ and
  $\mathsf{FinMem}(v, a)$, then $\mathsf{FinMem}(u, a)$.
\item \textbf{Comp-down:} If $u \leq u'$ and $\mathsf{Comp}(u', v)$,
  then $\mathsf{Comp}(u, v)$.
\end{itemize}

\subsection{Termination}

All definitions in the mutual block ($\mathsf{LeCode}$, $\mathsf{LeFunCode}$,
$\EvalFun$, $\mathsf{Comp}$, $\mathsf{CompFun}$, $\mathsf{Coherent}$,
$\mathsf{FinMem}$, and their auxiliaries) are terminating, although Agda's
termination checker requires a \texttt{TERMINATING} pragma for the
non-structural cases.  We sketch the informal arguments.

\medskip\noindent\textbf{LeCode and Comp.}
These are defined by pattern-matching on the pair of constructors.
Same-constructor cases recurse structurally: $\PiC{a}{f} \leq \PiC{b}{g}$
recurses on $(a,b)$ and on $\mathsf{LeFunCode}(f,g)$, which in turn
checks $v_i \leq \EvalFun(g, u_i)$ for each $(u_i,v_i) \in f$.
The result $\EvalFun(g, u_i)$ is built from values of entries of~$g$
glued by~$\sqcup$; it is bounded in size by~$g$.  Meanwhile $v_i$ is a
strict subterm of the first argument.  So all recursive calls operate on
strictly smaller data in the total-size measure $\mathsf{rk}$.
Cross-constructor cases return $\bot$ (empty type) immediately.
The same argument applies verbatim to $\mathsf{Comp}$ and $\mathsf{CompFun}$.

\medskip\noindent\textbf{Coherent.}
$\mathsf{Coherent}(u)$ is defined by structural recursion on~$u$.
On $\PiC{a}{f}$ it recurses into $\mathsf{Coherent}(a)$ and
$\mathsf{CoherentFunTail}(f)$, which walks the list~$f$ checking
$\mathsf{Coherent}$ on each key and value (strict subterms) and
$\mathsf{CoherentWith}$ between each entry and the tail (which calls
$\mathsf{Comp}$, already shown terminating).  No non-structural step occurs.

\medskip\noindent\textbf{FinMem.}
The only non-structural clause is $\mathsf{FinMem}(\Bot, a) = \mathsf{FinMem}(a, \U)$,
which swaps the arguments.  This can fire \emph{at most once}: after the swap,
the first argument is~$a$ (the original second argument), and every clause for a
non-$\Bot$ first argument either returns $\top$/$\bot$ immediately, or recurses
on strict subterms of both arguments.  In particular:
\begin{itemize}
\item If $a = \Bot$, we get $\mathsf{FinMem}(\Bot, \U) = \mathsf{FinMem}(\U, \U) = \top$.
\item If $a$ is non-$\Bot$, the subsequent recursive calls
  (e.g.\ $\mathsf{FinMem}(\PiC{a'}{f}, \U)$ reducing to $\mathsf{FinMem}(a', \U)$)
  always have a structurally smaller first argument and a non-$\Bot$ second argument,
  so the $\Bot$-swap never triggers again.
\end{itemize}
The auxiliary $\mathsf{FinMemFun}(g, a, f)$ recurses on the list~$g$,
calling $\mathsf{FinMem}$ on keys and values of~$g$ (strict subterms of the
original first argument) with second arguments $a$ and $\EvalFun(f, u_i)$
(derived from subterms of the original type code).
After the initial $\Bot$-swap, all recursion is well-founded on the
total size of the arguments.

\subsection{Decidability}

All the relations defined on finite elements are decidable.

\medskip\noindent\textbf{LeCode.}
Decidability is built into the definition via the numeric function
$\mathsf{leFinEl} : \FinEl \to \FinEl \to \mathbb{N}$, which mirrors the
structure of $\mathsf{LeCode}$ but returns a natural number (0 or positive).
Soundness and completeness lemmas establish that $\mathsf{leFinEl}(u,v) > 0$
if and only if $\mathsf{LeCode}(u,v)$.

\medskip\noindent\textbf{Comp, Coherent, FinMem.}
The file \texttt{FinMemDecidable.agda} provides decision procedures for
the remaining predicates, using $\mathsf{Dec}\;A = A + (A \to \bot)$:
\begin{align*}
  &\mathsf{decComp}   : (u\;v : \FinEl) \to \mathsf{Dec}(\mathsf{Comp}(u,v)) \\
  &\mathsf{decCoherent} : (u : \FinEl) \to \mathsf{Dec}(\mathsf{Coherent}(u)) \\
  &\mathsf{decFinMem} : (u\;a : \FinEl) \to \mathsf{Dec}(\mathsf{FinMem}(u,a))
\end{align*}
Each decision procedure follows the same case structure as the corresponding
definition, composing decisions through generic combinators for pairs
($\mathsf{dec\text{-}Pair}$), disjunctions ($\mathsf{dec\text{-}Or}$), and
implications ($\mathsf{dec\text{-}impl}$, using decidability of the premise
to either produce a witness or refute by applying the function to it).
All proofs are postulate-free.

\section{The logical relation}

The logical relation connects the domain-theoretic model to the syntax.
It is defined by mutual recursion on codes, with six mutually defined
predicates.  We describe the main ones.

\subsection{Term validity}

$\Val\;\Gamma\;M\;A\;u\;a$ asserts that term $M$ of type $A$ in context
$\Gamma$ is valid at value code $u$ and type code~$a$.  The definition is
by case analysis on the pair $(u, a)$:
\begin{itemize}
\item $\Val\;\Gamma\;M\;A\;u\;\Bot = \top$ \quad (trivially valid at bottom type).
\item At the universe: $\Val\;\Gamma\;M\;A\;u\;\U$ is non-trivial only when
  $u \in \{\U, \Prop, \PiC{b}{f}, \SigmaC{b}{f}\}$, in which case it
  requires $\ValTy\;\Gamma\;A\;\U$ (the type $A$ is valid at $\U$) together
  with $\ValTy\;\Gamma\;M\;u$ (the term $M$ is a valid type code~$u$).
\item At a Pi-type: $\Val\;\Gamma\;M\;A\;(\lambda g)\;(\PiC{b}{f})$ requires
  $\ValTy\;\Gamma\;A\;(\PiC{b}{f})$ together with application data: for each
  $(u_0, v_0) \in g$ and argument $N$ with $\hastype{\Gamma}{N}{A_0}$ and
  $\Val\;\Gamma\;N\;A_0\;u_0\;b$, one has
  $\Val\;\Gamma\;(\App{M}{N})\;(\substone{B_0}{N})\;v_0\;\EvalFun(f, u_0)$.
\item At a Sigma-type: $\Val\;\Gamma\;M\;A\;(u',v')\;(\SigmaC{b}{f})$
  requires $\ValTy\;\Gamma\;A\;(\SigmaC{b}{f})$ together with validity
  of both projections (see Section~\ref{sec:sigma-val} below).
\item All other combinations are trivially $\top$.
\end{itemize}

\subsection{Type validity}

$\ValTy\;\Gamma\;M\;a$ asserts that $M$ is a valid type at code~$a$.
The interesting cases are:
\begin{itemize}
\item $\ValTy\;\Gamma\;M\;\U$ requires a head reduction
  $M \Red \U$ together with $\conveq{\Gamma}{M}{\U}{\U}$.
\item $\ValTy\;\Gamma\;M\;(\PiC{b}{f})$ unpacks to specific
  types $A,B$ with $M \Red \Pitype{x{:}A}{B}$, typing evidence
  $\hastype{\Gamma}{A}{\U}$ and $\hastype{\Gamma,x{:}A}{B}{\U}$,
  domain validity $\ValTy\;\Gamma\;A\;b$, and \emph{edge functions}:
  for each $(u,v) \in f$ and well-typed argument $N$,
  $\ValTy\;\Gamma\;\substone{B}{N}\;v$.
\item $\ValTy\;\Gamma\;M\;(\SigmaC{b}{f})$ is analogous, with
  $M \Red \Sigmatype{x{:}A}{B}$.
\end{itemize}

\subsection{Equality}

$\EqVal\;\Gamma\;M\;N\;A\;u\;a$ bundles $\Val$ for both $M$ and $N$
together with an equality witness.  It follows the same case structure.
$\EqValTy\;\Gamma\;M\;N\;a$ is the corresponding type-level equality.

\subsection{Edge functions and selections}

The records for $\ValTy$ at $\PiC{b}{f}$ and $\SigmaC{b}{f}$ contain
\emph{edge functions} that witness how the codomain type varies with the
input.  For instance, the value edge in the Pi case has the form:
\[
  \text{for all } (u,v) \text{ selected from } f, \text{ and }
  N \text{ with } \hastype{\Gamma}{N}{A} \text{ and }
  \Val\;\Gamma\;N\;A\;u\;b,
  \text{ one has }
  \ValTy\;\Gamma\;\substone{B}{N}\;v.
\]
Here $(u,v)$ is \emph{selected} from~$f$ in the sense of
$\mathsf{Selection}(f, u, v)$: each entry $(u_i, v_i)$ in $f$ is either
skipped (contributing $(\Bot,\Bot)$) or taken (combining via $\sqcup$
with a compatibility proof), yielding a pair $(u,v)$ that satisfies
$u \leq \EvalFun(f, u)$ and is built from subterms of~$f$.

Similarly, the application data in $\Val$ at $(\lambda g, \PiC{b}{f})$
requires: for all $(u,v)$ selected from~$g$ and well-typed argument $N$ with
$\Val\;\Gamma\;N\;A_0\;u\;b$, one has
$\Val\;\Gamma\;(\App{M}{N})\;\substone{B_0}{N}\;v\;\EvalFun(f,u)$.

\subsection{Termination of the logical relation}

The four mutually defined predicates $\Val$, $\EqVal$, $\ValTy$, $\EqValTy$
and their associated record types form a single mutual block, marked
\texttt{TERMINATING} in the formalisation.  The well-foundedness argument
is more subtle than for the domain-level predicates: the recursion cannot
be measured by the type code~$a$ alone.

\medskip\noindent\textbf{The difficulty at the universe.}
Consider $\Val\;\Gamma\;M\;A\;(\PiC{a'}{f'})\;\U$.
This reduces to $\ValTy\;\Gamma\;A\;\U$ paired with
$\ValTy\;\Gamma\;M\;(\PiC{a'}{f'})$.  The second component recurses at
type code $\PiC{a'}{f'}$, which is not a subterm of the original type code
$\U$---it is part of the \emph{value code}.  Moreover $a'$ can itself be
$\U$, so the recursion is not simply structural on either code.

\medskip\noindent\textbf{The measure: depth of $\mathsf{FinMem}(u,a)$.}
The relation $\Val\;\Gamma\;M\;A\;u\;a$ is only meaningful when
$\mathsf{FinMem}(u,a)$ holds---this is a precondition maintained by the
adequacy proof.  The correct well-foundedness measure is the
\emph{size of the $\mathsf{FinMem}(u,a)$ derivation}: at each recursive
call, the corresponding membership proof is a strict sub-derivation.

We trace this through the cases:

\begin{itemize}
\item \textbf{$a = \Bot$:} $\Val$ returns $\top$, no recursion.

\item \textbf{$a = \U$, $u = \PiC{a'}{f'}$:}
  The membership $\mathsf{FinMem}(\PiC{a'}{f'}, \U)$ consists of
  $\mathsf{FinMem}(a', \U)$, $\mathsf{FinMemAllU}(f', a')$, and
  $\mathsf{CoherentFunTail}(f')$.
  The definition produces $\ValTy\;\Gamma\;M\;(\PiC{a'}{f'})$, which
  unfolds to $\mathsf{RValTyPi}$ containing:
  \begin{itemize}
  \item $\ValTy\;\Gamma\;A_0\;a'$, with membership
    $\mathsf{FinMem}(a', \U)$---a sub-derivation of the original
    $\mathsf{FinMem}(\PiC{a'}{f'}, \U)$.  But this call is at $(a', \U)$
    which itself unfolds further: if $a' = \PiC{a''}{f''}$, the
    membership $\mathsf{FinMem}(a'', \U)$ is again strictly smaller.
    Since the membership derivation is finite, this chain terminates.
  \item Edge functions producing $\ValTy\;\Gamma\;\substone{B}{N}\;v$
    for $(u_0,v_0)$ selected from~$f'$, where the membership evidence for
    $v_0$ at~$\U$ comes from $\mathsf{FinMemAllU}(f', a')$---again a
    sub-derivation.
  \end{itemize}
  The case $u = \SigmaC{a'}{f'}$ at $\U$ is analogous.

\item \textbf{$a = \PiC{b}{f}$, $u = \lambda g$:}
  The membership $\mathsf{FinMem}(\lambda g, \PiC{b}{f})$ consists of
  $\mathsf{FinMemFun}(g, b, f)$, $\mathsf{CoherentFun}(g)$, and
  $\mathsf{FinMem}(\PiC{b}{f}, \U)$.
  The application data requires
  $\Val\;\Gamma\;(\App{M}{N})\;\substone{B_0}{N}\;v\;\EvalFun(f,u_0)$
  for $(u_0,v_0)$ selected from~$g$.  The membership
  $\mathsf{FinMem}(v_0, \EvalFun(f, u_0))$ is derivable from
  $\mathsf{FinMemFun}(g, b, f)$---a sub-derivation.
  The bundled $\ValTy\;\Gamma\;A\;(\PiC{b}{f})$ recurses at the
  membership $\mathsf{FinMem}(\PiC{b}{f}, \U)$, which is a component of
  the original membership.

\item \textbf{$a = \SigmaC{b}{f}$, $u = (u', v')$:}
  The membership $\mathsf{FinMem}((u',v'), \SigmaC{b}{f})$ contains
  $\mathsf{FinMem}(u', b)$ and $\mathsf{FinMem}(v', \EvalFun(f, u'))$.
  The recursive calls $\Val\;\Gamma\;\Fst{M}\;A_0\;u'\;b$ and
  $\Val\;\Gamma\;\Snd{M}\;\substone{B_0}{\Fst{M}}\;v'\;\EvalFun(f,u')$
  use exactly these sub-derivations as their membership evidence.

\item \textbf{All other $(u,a)$:} $\Val$ returns $\top$, no recursion.
\end{itemize}

\medskip\noindent\textbf{Summary.}
The recursion is well-founded on the size of the $\mathsf{FinMem}(u,a)$
derivation.  At each recursive call---whether descending into domain codes,
edge functions, application data, or projections---the corresponding
membership evidence is a strict sub-derivation.  The universe case, where
$a = \U$ and the recursion shifts to the value code~$u$, is controlled by
the fact that $\mathsf{FinMem}(u, \U)$ decomposes $u$ into strictly smaller
membership sub-proofs (domain code, codomain entries), even though $u$ is
not a subterm of~$\U$.

\medskip\noindent\textbf{Positivity.}
The records ($\mathsf{RValPi}$, $\mathsf{RValTyPi}$, etc.)
are marked \texttt{NO\_POSITIVITY\_CHECK} in the formalisation because
$\Val$ and $\EqVal$ appear in negative position within the edge
functions (as hypotheses: ``for all $N$ with
$\Val\;\Gamma\;N\;A\;u\;b$, \ldots'').  This is sound because the
edge functions are \emph{stored data}, not computationally inspected
by the definition of $\Val$ itself---they are produced by the adequacy
proof, which constructs them by induction on typing derivations.

\subsection{Adequacy}

The \emph{adequacy theorem} (Theorem~2 of Coquand--Huber 2018, extended to
$\Sigma$) states that typability implies validity.  In the two-substitution form:

\begin{theorem}[Adequacy]
If $\hastype{\Gamma}{M}{A}$, then for any coherent environment $\rho$ with
a valid substitution $\sigma$ into a context $H$, and any codes $u$, $a$ such
that $M$ evaluates to $u$ at $\rho$ and $A$ evaluates to $a$ at $\rho$ with
$\mathsf{FinMem}(u,a)$, we have $\Val\;H\;\sigma(M)\;\sigma(A)\;u\;a$.
\end{theorem}

\noindent
The proof proceeds by mutual induction on the typing derivation, with a
parallel statement for conversion ($\conveq{\Gamma}{M}{N}{A}$ implies
$\EqVal$) and a two-substitution variant ($M$ under two related substitutions
gives $\EqVal$).

\medskip\noindent
The injectivity results and subject reduction below are
\emph{corollaries} of adequacy: one evaluates at the trivial bottom
environment $\rho_\bot$ to extract head-reduction and conversion data from
the logical relation.

\section{Pi injectivity}

\begin{theorem}[Pi injectivity --- Corollary 6]
  \label{thm:pi-conv}
  If\/ $\conveq{\Gamma}{A_0}{\Pitype{x{:}B_1}{F_1}}{\U}$,
  then there exist $B_0$, $F_0$ such that
  \begin{enumerate}
    \item $A_0 \Red \Pitype{x{:}B_0}{F_0}$,
    \item $\conveq{\Gamma}{B_0}{B_1}{\U}$,
    \item $\conveq{\Gamma, x{:}B_0}{F_0}{F_1}{\U}$.
  \end{enumerate}
\end{theorem}

\begin{corollary}[Pi--Pi injectivity]
  If\/ $\conveq{\Gamma}{\Pitype{x{:}A_0}{B_0}}{\Pitype{x{:}A_1}{B_1}}{\U}$,
  then
  \[
    \conveq{\Gamma}{A_0}{A_1}{\U}
    \qquad\text{and}\qquad
    \conveq{\Gamma, x{:}A_0}{B_0}{B_1}{\U}.
  \]
\end{corollary}

\begin{proof}[Proof outline]
  The proof proceeds by domain-theoretic adequacy:
  \begin{enumerate}
    \item From the conversion, extract $\hastype{\Gamma}{A_0}{\U}$
      by presupposition.
    \item Apply conversion soundness at the bottom environment
      $\rho_\bot$ to transfer
      $\mathsf{EvalRel}(\Pi B_1\,F_1, \rho_\bot, \PiC{\bot}{\mathsf{nil}})$
      to $\mathsf{EvalRel}(A_0, \rho_\bot, \PiC{\bot}{\mathsf{nil}})$.
    \item Apply bundled equality adequacy (\texttt{adequacyEqSub2})
      to obtain $\mathsf{EqVal2}$ at the $\PiC{\bot}{\mathsf{nil}}$
      code, which unfolds to $\mathsf{EqValTyPi2}$ containing the
      head reduction and domain/codomain conversions.
    \item Since $\Pi$ is a head normal form, reduction uniqueness
      (\texttt{Red-unique-Pi}) gives exact equalities.
  \end{enumerate}
\end{proof}

\section{Sigma injectivity}

\begin{theorem}[Sigma injectivity]
  \label{thm:sigma-conv}
  If\/ $\conveq{\Gamma}{A_0}{\Sigmatype{x{:}B_1}{F_1}}{\U}$,
  then there exist $B_0$, $F_0$ such that
  \begin{enumerate}
    \item $A_0 \Red \Sigmatype{x{:}B_0}{F_0}$,
    \item $\conveq{\Gamma}{B_0}{B_1}{\U}$,
    \item $\conveq{\Gamma, x{:}B_0}{F_0}{F_1}{\U}$.
  \end{enumerate}
\end{theorem}

\begin{corollary}[Sigma--Sigma injectivity]
  If\/ $\conveq{\Gamma}{\Sigmatype{x{:}A_0}{B_0}}{\Sigmatype{x{:}A_1}{B_1}}{\U}$,
  then
  \[
    \conveq{\Gamma}{A_0}{A_1}{\U}
    \qquad\text{and}\qquad
    \conveq{\Gamma, x{:}A_0}{B_0}{B_1}{\U}.
  \]
\end{corollary}

\begin{proof}[Proof outline]
  The proof follows the same strategy as Pi injectivity:
  \begin{enumerate}
    \item Extract $\hastype{\Gamma}{A_0}{\U}$ by presupposition.
    \item Transfer
      $\mathsf{EvalRel}(\Sigma B_1\,F_1, \rho_\bot, \SigmaC{\bot}{\mathsf{nil}})$
      to $\mathsf{EvalRel}(A_0, \rho_\bot, \SigmaC{\bot}{\mathsf{nil}})$
      via conversion soundness.
    \item Apply bundled equality adequacy to obtain
      $\mathsf{EqValTySigma2}$ containing head reduction and
      domain/codomain conversions.
    \item Since $\Sigma$ is a head normal form, reduction uniqueness
      (\texttt{Red-unique-Sigma}) gives exact equalities.
  \end{enumerate}
\end{proof}

\section{Subject reduction}

As an application of Pi and Sigma injectivity, we prove subject
reduction for single-step head reduction.  The proof requires two
mutually defined theorems due to the Snd case.

\begin{theorem}[Subject reduction and subject conversion]
  \label{thm:subject-red}
  The following are proved by mutual induction on the typing
  derivation:
  \begin{enumerate}
    \item \textbf{Subject reduction.}\; If\/
      $\hastype{\Gamma}{M}{A}$ and $M \leadsto_1 N$, then
      $\hastype{\Gamma}{N}{A}$.
    \item \textbf{Subject conversion.}\; If\/
      $\hastype{\Gamma}{M}{A}$ and $M \leadsto_1 N$, then
      $\conveq{\Gamma}{M}{N}{A}$.
  \end{enumerate}
\end{theorem}

\noindent
The mutual definition is necessary because of the \textsc{Snd} case:
when $M \leadsto_1 M'$ and we have $\hastype{\Gamma}{\Snd{M}}{\substone{B}{\Fst{M}}}$,
subject reduction for $\Snd{M} \leadsto_1 \Snd{M'}$ must produce
$\hastype{\Gamma}{\Snd{M'}}{\substone{B}{\Fst{M}}}$.  But
the direct application of \textsc{Snd} gives type $\substone{B}{\Fst{M'}}$.
To bridge the gap, we need $\conveq{\Gamma}{\Fst{M}}{\Fst{M'}}{A}$,
which requires subject conversion (not just subject reduction)
applied to~$M$.

\begin{proof}[Proof outline]
  By mutual induction on the typing derivation, case-splitting on
  the head reduction step.

  \medskip\noindent\textbf{Subject reduction cases:}
  \begin{itemize}
    \item \textsc{Conv} and \textsc{Prop-U}: peel off and recurse.
    \item \textsc{App} with \textsc{HR-App} ($f \leadsto_1 f'$):
      induction gives $\hastype{\Gamma}{f'}{\Pitype{x{:}A}{B}}$;
      rebuild with \textsc{App}.
    \item \textsc{App} with \textsc{HR-Beta}
      ($\App{(\Lamterm{x{:}A'}{M'})}{a} \leadsto_1 \substone{M'}{a}$):
      the key case.  Use Pi injectivity to extract the body typing
      $\hastype{\Gamma, x{:}A_0}{M'}{B_0}$ from the lambda
      derivation (walking through \textsc{Conv} layers), then apply
      substitution.  The helper lemma \texttt{ty-Lam-body} performs
      this extraction.
    \item \textsc{Fst} with \textsc{HR-Fst} ($M \leadsto_1 M'$):
      induction gives $\hastype{\Gamma}{M'}{\Sigmatype{x{:}A}{B}}$;
      rebuild with \textsc{Fst}.
    \item \textsc{Fst} with \textsc{HR-Beta-Fst}
      ($\Fst{\MkPair{M}{N}} \leadsto_1 M$):
      use Sigma injectivity to extract
      $\hastype{\Gamma}{M}{A}$ from the MkPair derivation.
      The helper \texttt{ty-MkPair-components} performs this
      extraction.
    \item \textsc{Snd} with \textsc{HR-Snd} ($M \leadsto_1 M'$):
      induction on subject conversion gives
      $\conveq{\Gamma}{M}{M'}{{\Sigmatype{x{:}A}{B}}}$, hence
      $\conveq{\Gamma}{\Fst{M}}{\Fst{M'}}{A}$ by \textsc{Fst-Cong}.
      Subject reduction gives
      $\hastype{\Gamma}{\Snd{M'}}{\substone{B}{\Fst{M'}}}$;
      type conversion via $\Fst{M} = \Fst{M'}$ yields
      $\hastype{\Gamma}{\Snd{M'}}{\substone{B}{\Fst{M}}}$.
    \item \textsc{Snd} with \textsc{HR-Beta-Snd}
      ($\Snd{\MkPair{M}{N}} \leadsto_1 N$):
      use Sigma injectivity and \texttt{ty-MkPair-components}
      to extract $\hastype{\Gamma}{N}{\substone{B}{M}}$, then
      convert using $\conveq{\Gamma}{M}{\Fst{\MkPair{M}{N}}}{A}$
      (the symmetric Beta-Fst).
  \end{itemize}

  \medskip\noindent\textbf{Subject conversion} follows from subject
  reduction: given $\hastype{\Gamma}{M}{A}$ and $M \leadsto_1 N$,
  subject reduction gives $\hastype{\Gamma}{N}{A}$, and the
  corresponding conversion rule for the head reduction step
  ($\beta$, $\beta$-fst, $\beta$-snd, or congruence) gives
  $\conveq{\Gamma}{M}{N}{A}$.

  \medskip\noindent\textbf{Key helper lemmas:}
  \begin{itemize}
    \item \texttt{ty-Lam-body}: If
      $\hastype{\Gamma}{\Lamterm{x{:}A'}{M}}{\Pitype{x{:}A}{B}}$,
      then $\hastype{\Gamma, x{:}A}{M}{B}$.  Proved by walking
      through \textsc{Conv} (using Pi injectivity) and eliminating
      \textsc{Prop-U} (since $\U$ cannot head-reduce to $\Pi$).
    \item \texttt{ty-MkPair-components}: If
      $\hastype{\Gamma}{\MkPair{M}{N}}{\Sigmatype{x{:}A}{B}}$,
      then $\hastype{\Gamma}{M}{A}$ and
      $\hastype{\Gamma}{N}{\substone{B}{M}}$.  Proved by walking
      through \textsc{Conv} (using Sigma injectivity) and
      eliminating \textsc{Prop-U}.
  \end{itemize}
\end{proof}

\section{Validity for Sigma types}\label{sec:sigma-val}

We describe the extension of the logical relation (validity) to handle
$\Sigma$-types.
The key new difficulty compared to $\Pi$-types is in the head-reduction
transport lemma.

\subsection{Codes and projections}

The set $\FinEl$ of codes includes:
\[
  u,v ::= \Bot \mid \U \mid \Prop \mid \lambda g \mid \PiC{b}{f}
         \mid \SigmaC{b}{f} \mid (u,v)
\]
A code $\SigmaC{b}{f}$ represents a $\Sigma$-type whose domain has code~$b$
and whose codomain is the finite function~$f$.
A code $(u,v)$ represents a pair value.

We use a uniform projection notation for both terms and codes:
\[
  \pj{M}{1},\quad \pj{M}{2} \qquad\text{(first and second projection of a term)}
\]
\[
  \pj{w}{1},\quad \pj{w}{2} \qquad\text{(first and second projection of a code)}
\]
On codes, the projections are defined by:
\[
  \pj{(u,v)}{1} = u, \qquad \pj{w}{1} = \Bot \text{ otherwise}
\]
\[
  \pj{(u,v)}{2} = v, \qquad \pj{w}{2} = \Bot \text{ otherwise}
\]

\subsection{Term validity at $\Sigma$}

\begin{definition}[Term validity at $\Sigma$]
We define $\Val\;\Gamma\;M\;T\;w\;\SigmaC{b}{f}$ to hold when:
\begin{enumerate}
\item $\ValTy\;\Gamma\;T\;(\SigmaC{b}{f})$ (type validity of~$T$), which
  includes $T \Red \Sigmatype{x{:}A}{B}$ with $\hastype{\Gamma}{A}{\U}$ and
  $\hastype{\Gamma, x{:}A}{B}{\U}$, together with the edge functions;
\item $\Val\;\Gamma\;\pj{M}{1}\;A\;\pj{w}{1}\;b$ (validity of the
  first projection);
\item $\Val\;\Gamma\;\pj{M}{2}\;\substone{B}{\pj{M}{1}}\;\pj{w}{2}\;f(\pj{w}{1})$
  (validity of the second projection).
\end{enumerate}
\end{definition}

\begin{remark}
When $w$ is not a pair $(u,v)$, we have $\pj{w}{1} = \Bot$ and
$\pj{w}{2} = \Bot$.  Since $\Val$ at code $\Bot$ is trivially $\top$,
conditions (2) and (3) are automatically satisfied.  This means there is no
need for separate case analysis on whether $w$ is a pair or not: the
definition is \emph{uniform} in~$w$.
\end{remark}

\begin{remark}
Compared to the $\Pi$-case, where term validity at $\PiC{b}{f}$ is
defined for $w = \lambda g$ and stores
$\Val\;\Gamma\;(\App{M}{N})\;(\substone{B}{N})\;v\;(f(u))$, the type
$\substone{B}{N}$ does not mention~$M$.  For $\Sigma$, the second
component's type $\substone{B}{\pj{M}{1}}$ \emph{does} mention~$M$.
This is the source of the difficulty in head-reduction transport.
\end{remark}

\subsection{Type validity at $\Sigma$}

\begin{definition}[Type validity at $\Sigma$]
$\ValTy\;\Gamma\;T\;(\SigmaC{b}{f})$ holds when:
\begin{itemize}
\item $T \Red \Sigmatype{x{:}A}{B}$ and
  $\conveq{\Gamma}{T}{\Sigmatype{x{:}A}{B}}{\U}$;
\item $\hastype{\Gamma}{A}{\U}$ and $\hastype{\Gamma, x{:}A}{B}{\U}$;
\item $\ValTy\;\Gamma\;A\;b$ (domain type validity);
\item For each $(u,v) \in f$ and $N$ with $\hastype{\Gamma}{N}{A}$ and
  $\Val\;\Gamma\;N\;A\;u\;b$, we have $\ValTy\;\Gamma\;\substone{B}{N}\;v$
  (edge function for values);
\item Similarly for the equality edge.
\end{itemize}
\end{definition}

\section{Type-equality transport}

\begin{lemma}[Transport along type equality]\label{lem:transport}
For all codes $u$ and $a$:
\[
  \EqValTy\;\Gamma\;C\;C'\;a \;\;\Longrightarrow\;\;
  \Val\;\Gamma\;N\;C\;u\;a \;\;\Longrightarrow\;\;
  \Val\;\Gamma\;N\;C'\;u\;a
\]
\end{lemma}

\begin{proof}
By induction on $a$.  The type parameter $C$ appears in $\Val\;\Gamma\;N\;C\;u\;a$
only in two cases: $a = \PiC{b}{f}$ with $u = \lambda g$, and
$a = \SigmaC{b}{f}$ with $u = (u',v')$.  In these cases the validity
record stores a head reduction $C \Red \Pitype{x{:}A}{B}$
or $C \Red \Sigmatype{x{:}A}{B}$, and $\EqValTy\;\Gamma\;C\;C'\;a$
provides the corresponding data for~$C'$, allowing
the record to be rebuilt.  In all other cases---including $a = \U$,
where $\Val$ depends on~$N$ but not on~$C$---the result is immediate.
\end{proof}

\begin{remark}
This lemma plays a central role in the $\Sigma$ case of
head-reduction transport (Lemma~\ref{lem:headred}, Step~4), where it
transports $\Val$ from type $\substone{B}{\pj{M'}{1}}$ to type
$\substone{B}{\pj{M}{1}}$.
For $\Pi$-types alone, this lemma is not needed in head-reduction transport.
\end{remark}

\section{Head-reduction transport}

The central lemma for adequacy is:

\begin{lemma}[Head-reduction produces equality]\label{lem:headred}
Given:
\begin{itemize}
\item $M \Red M'$ and $\conveq{\Gamma}{M}{M'}{T}$,
\item $\Val\;\Gamma\;M'\;T\;u\;a$ \quad (validity of the reduct),
\end{itemize}
we can conclude:
\[
  \EqVal\;\Gamma\;M'\;M\;T\;u\;a
\]
which bundles $\Val\;\Gamma\;M\;T\;u\;a$ and $\Val\;\Gamma\;M'\;T\;u\;a$
and the equality $\EqVal\;\Gamma\;M'\;M\;T\;u\;a$.
\end{lemma}

\begin{remark}
The return type is $\EqVal$ (not just $\Val$).  This is essential
for the $\Sigma$ case: the equality at the first projection is needed to
transport the second projection's type.
\end{remark}

\subsection{The $\Pi$ case}

For $a = \PiC{b}{f}$ and $u = \lambda g$, the validity data for~$M'$
stores, for each $(u_0, v_0) \in g$ and argument~$N$:
\[
  \Val\;\Gamma\;(\App{M'}{N})\;(\substone{B_0}{N})\;v_0\;(f(u_0))
\]
Since $M \Red M'$, we have $\App{M}{N} \Red \App{M'}{N}$.
The type $\substone{B_0}{N}$ does not mention~$M$, so the induction hypothesis
applies directly at code $(v_0, f(u_0))$:
\[
  \EqVal\;\Gamma\;(\App{M'}{N})\;(\App{M}{N})\;(\substone{B_0}{N})\;v_0\;(f(u_0))
\]
No type transport is needed.

\subsection{The $\Sigma$ case}\label{sec:sigma}

For $a = \SigmaC{b}{f}$, we work with the uniform definition.
The validity data for~$M'$ includes:
\begin{align}
  &\Val\;\Gamma\;\pj{M'}{1}\;A\;\pj{w}{1}\;b  \label{eq:fstM'}\\
  &\Val\;\Gamma\;\pj{M'}{2}\;\substone{B}{\pj{M'}{1}}\;\pj{w}{2}\;f(\pj{w}{1})
    \label{eq:sndM'}
\end{align}

We need to produce the same data for~$M$, plus equality.

\medskip
\noindent\textbf{Step 1: First projection.}
From $M \Red M'$ we get $\pj{M}{1} \Red \pj{M'}{1}$.  From
$\conveq{\Gamma}{M}{M'}{\Sigmatype{x{:}A}{B}}$ we derive (by the congruence
rule for projections):
\[
  \conveq{\Gamma}{\pj{M}{1}}{\pj{M'}{1}}{A}
\]
Together with~\eqref{eq:fstM'}, the induction hypothesis at code
$(\pj{w}{1}, b)$ gives:
\begin{equation}\label{eq:eqfst}
  \EqVal\;\Gamma\;\pj{M'}{1}\;\pj{M}{1}\;A\;\pj{w}{1}\;b
\end{equation}
This bundles $\Val\;\Gamma\;\pj{M}{1}\;A\;\pj{w}{1}\;b$.

\medskip
\noindent\textbf{Step 2: Type transport via the edge function.}
The equality~\eqref{eq:eqfst} and the equality edge function from $\ValTy$ at
$\SigmaC{b}{f}$ give:
\begin{equation}\label{eq:eqty}
  \EqValTy\;\Gamma\;\substone{B}{\pj{M'}{1}}\;\substone{B}{\pj{M}{1}}\;f(\pj{w}{1})
\end{equation}
This is the key step: the \emph{equality} edge function converts the equality of
\emph{values} ($\pj{M'}{1} = \pj{M}{1}$) into an equality of \emph{types}
($\substone{B}{\pj{M'}{1}} = \substone{B}{\pj{M}{1}}$).  This step has no
analogue in the $\Pi$ case.

Note that the \emph{value} edge (which only takes $\Val$ data) would not suffice
here: we genuinely need the \emph{equality} at the first projection to produce
the type equality for the transport.  This is why
Lemma~\ref{lem:headred} must return $\EqVal$ rather than just $\Val$.

\medskip
\noindent\textbf{Step 3: Second projection.}
From $M \Red M'$ we get $\pj{M}{2} \Red \pj{M'}{2}$.  The congruence
rule for the second projection, applied to
$\conveq{\Gamma}{M'}{M}{\Sigmatype{x{:}A}{B}}$
(note the swap, so that $\pj{M'}{1}$ appears in the type), gives:
\[
  \conveq{\Gamma}{\pj{M'}{2}}{\pj{M}{2}}{\substone{B}{\pj{M'}{1}}}
\]
Together with~\eqref{eq:sndM'}, the induction hypothesis at code
$(\pj{w}{2}, f(\pj{w}{1}))$ gives:
\begin{equation}\label{eq:eqsnd}
  \EqVal\;\Gamma\;\pj{M'}{2}\;\pj{M}{2}\;\substone{B}{\pj{M'}{1}}\;\pj{w}{2}\;f(\pj{w}{1})
\end{equation}
In particular, $\Val\;\Gamma\;\pj{M}{2}\;\substone{B}{\pj{M'}{1}}\;\pj{w}{2}\;f(\pj{w}{1})$.

\medskip
\noindent\textbf{Step 4: Transport.}
The validity data for~$M$ at $\Sigma$ requires:
\[
  \Val\;\Gamma\;\pj{M}{2}\;\substone{B}{\pj{M}{1}}\;\pj{w}{2}\;f(\pj{w}{1})
\]
We have $\Val$ at $\substone{B}{\pj{M'}{1}}$ from Step~3, and $\EqValTy$ between
$\substone{B}{\pj{M'}{1}}$ and $\substone{B}{\pj{M}{1}}$ from Step~2.
Lemma~\ref{lem:transport} gives
$\Val\;\Gamma\;\pj{M}{2}\;\substone{B}{\pj{M}{1}}\;\pj{w}{2}\;f(\pj{w}{1})$.

\section{Bundling requirements}

For $\Pi$, $\U$, and $\Prop$ alone, the following simpler choices suffice:
\begin{itemize}
\item Head reduction ($\mathsf{Red}$) stores only $T \Red \Pitype{x{:}A}{B}$,
  without the convertibility judgment $\conveq{\Gamma}{T}{\Pitype{x{:}A}{B}}{\U}$.
\item The head-reduction transport lemma can return just $\Val$
  (validity of the expanded term), without the equality $\EqVal$.
\item Term validity $\Val\;\Gamma\;M\;T\;u\;a$ need not be bundled with
  type validity $\ValTy\;\Gamma\;T\;a$.
\end{itemize}
For $\Sigma$-types, all three must be strengthened:
\begin{enumerate}
\item \textbf{$\mathsf{Red}$ must bundle convertibility.}
  The head-reduction transport for $\Sigma$ needs to derive
  $\conveq{\Gamma}{\pj{M}{1}}{\pj{M'}{1}}{A}$ (via the congruence
  rule for projections).  This congruence rule requires
  $\conveq{\Gamma}{M}{M'}{\Sigmatype{x{:}A}{B}}$, which is obtained from
  the input $\conveq{\Gamma}{M}{M'}{T}$ by converting the type using
  $\conveq{\Gamma}{T}{\Sigmatype{x{:}A}{B}}{\U}$---the convertibility
  stored in the type validity record alongside the head reduction
  $T \Red \Sigmatype{x{:}A}{B}$.

\item \textbf{Head-reduction transport must return $\EqVal$.}
  The equality $\EqVal$ at the first projection is needed to invoke
  the equality edge function (Step~2), which produces the type equality
  $\EqValTy\;\Gamma\;\substone{B}{\pj{M'}{1}}\;\substone{B}{\pj{M}{1}}\;f(\pj{w}{1})$
  used in the transport (Step~4).

\item \textbf{$\Val$ must be bundled with $\ValTy$.}
  Step~2 uses the equality edge function from
  $\ValTy\;\Gamma\;T\;(\SigmaC{b}{f})$.
  This must be accessible from within the term validity data.
  Therefore $\Val\;\Gamma\;M\;T\;w\;(\SigmaC{b}{f})$ must include
  $\ValTy\;\Gamma\;T\;(\SigmaC{b}{f})$ as a component.
\end{enumerate}

\section{Agda formalization}

The entire development is formalised in Agda with flags
\texttt{--without-K --exact-split} (no \texttt{--type-in-type}) and
\textbf{0 postulates} throughout.

\medskip\noindent\textbf{Core files:}
\begin{itemize}
  \item \texttt{RawSyntax.agda} --- raw terms ($\Pi$, $\Sigma$,
    $\lambda$, App, MkPair, Fst, Snd, U, Prop), substitution,
    weakening.
  \item \texttt{TypingRules.agda} --- typing and conversion judgments.
  \item \texttt{PaperSemantics.agda} --- trusted kernel: finite
    elements ($\mathsf{FinEl}$, $\mathsf{FinFun}$), information
    ordering, coherence, finite membership.  No postulates.
  \item \texttt{RawSemantics.agda} --- selection-based evaluation
    relation.  No postulates.
  \item \texttt{TypingSemantics.agda} --- typing and conversion
    soundness.  0 postulates.
  \item \texttt{Reduction.agda} --- head reduction
    ($\mathsf{HeadRed1}$, $\mathsf{Red}$).
\end{itemize}

\medskip\noindent\textbf{Validity stack} (Validity5 series):
\begin{itemize}
  \item \texttt{Validity5Core.agda} --- base definitions of
    $\mathsf{Val2}$/$\mathsf{EqVal2}$ with record types.
  \item \texttt{Validity5DownUpRestrict.agda} --- monotonicity:
    downward, upward, and restriction in the code argument.
  \item \texttt{Validity5Fwd.agda} --- forward lemmas.
  \item \texttt{Validity5SymTrans.agda} --- symmetry and
    transitivity for $\mathsf{EqVal2}$.
  \item \texttt{Validity5Sup.agda} --- sup closure.
  \item \texttt{Validity5Lemmas.agda} --- collected utility lemmas.
\end{itemize}

\medskip\noindent\textbf{Main results:}
\begin{itemize}
  \item \texttt{Adequacy5.agda} + \texttt{Adequacy5Cases.agda} ---
    adequacy proof (two-substitution form).  0 postulates.
  \item \texttt{Adequacy5Helpers.agda},
    \texttt{Adequacy5HeadRed.agda} --- helper lemmas for adequacy.
  \item \texttt{Injectivity5.agda} --- Pi and Sigma injectivity.
    0 postulates.
  \item \texttt{SubjectReduction5.agda} --- subject reduction +
    subject conversion (mutual).  0 postulates.
\end{itemize}
