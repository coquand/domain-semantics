Recovering derivations by bounded proof search
=============================================

The natural interface
---------------------

Use an exhaustive bounded proof procedure. There is no need to number
derivations, decide equality of derivations, or encode them into naturals.

For a type A, the checked interface Procedure.Bounded in
BoundedWitnessSearch.seg has two fields:

    run      : Nat -> A + 1
    complete : A -> || sum n, Succeeds (run n) ||

Here Succeeds (inl a) = Top and Succeeds (inr tt) = Empty. The second
outcome means that this run has found no witness. It makes no assertion
that A is empty. An implementation for derivations will use n as a bound
on the finite proof search.

Completeness need not recover the supplied element a, and the result of
run n need not be monotone or coherent as n increases. All that is needed
is eventual success whenever an actual witness exists. An explicit size
bound and a proof of success at that bound imply the stated completeness
field, but the interface only asks for the resulting mere existence.

Procedure.Extract.recover constructs

    || A || -> A

for every instance of this interface. A need not be a set.

Why the extraction is legitimate
--------------------------------

The success of a particular run is a decidable proposition: inspect its
sum tag, without comparing the returned values. Let P(n) be that success
proposition. The type

    sum n, P(n) * Before(n,P)

of first successful budgets is a proposition. Before(n,P) is the finite
prefix of failed tests, defined structurally:

    Before(0,P)     = Top
    Before(n+1,P)   = not P(0) * Before(n, k |-> P(k+1)).

Two such budgets agree: at zero, a positive test contradicts a nonempty
failure prefix; at successors, remove their first failed tests and apply
induction. The remaining evidence is proposition-valued. This proof uses
no ordering of derivations, and not even the arithmetic order on Nat.

An actual success at n permits a finite search through budgets 0,...,n.
The negative result of that finite search contradicts the given success,
so it returns the first successful budget. Because the target is a
proposition, both mere existence of a successful budget and mere
inhabitation of A can be eliminated into it. Finally inspect run at the
chosen budget and return its successful value.

The successful budget is canonical relative to run. The returned witness
need not be the derivation originally used to prove inhabitation.

Application to the object theory
--------------------------------

For J = (Gamma |- M : A), use A = Syntax.Der n J. A goal-directed proof
procedure should construct derivations with the existing rule constructors.
It does not need a separate checker for complete derivation certificates.

At a finite term bound k, form a finite list of applicable rule instances
for the current judgement. An instance specifies finitely many premise
judgements and a constructor that assembles their derivations. Terms with
bounded syntax depth in a fixed finite context form a finite family.
Rule tags are finite. Root syntax determines many of the parameters;
the remaining intermediate terms can be drawn from that finite family.
The required syntactic comparisons are decidable.

For example, an instance of conversion with conclusion Gamma |- M : A
chooses an intermediate type B from this finite family. Its premises are

    Gamma |- M : B
    Gamma |- B = A : U
    Gamma |- A : U.

The constructor is Syntax.ty-conv. A transitivity instance similarly
chooses an intermediate term and has two equality premises. Equality
proofs are built with the explicit equality constructors; the procedure
does not ask an oracle whether two terms are definitionally equal.

Keep a height bound h separate from the term bound k in the implementation:

    prove(0,k,J)       = not found
    prove(h+1,k,J)     = inspect the finite rule instances for J;
                        call prove(h,k,...) on each instance's premises;
                        return the first instance whose premises succeed.

Zero-premise rules can succeed at the first successor height. The public
procedure can take run(n,J) = prove(n,n,J). Finite exploration is confined
to rule instances and their premise goals. The output is built as a
derivation, rather than decoded from a global derivation number.

Soundness is built into the output type: every successful branch applies
an actual inference constructor to actual premise derivations. Prove
completeness by induction on an input derivation, with independent bounds
on its height and on every syntactic annotation in the tree. The induction
hypothesis should quantify over all larger bounds. At the root, the actual
rule instance occurs among the finite candidates; the hypotheses ensure
that its premises succeed. Some earlier candidate might also succeed,
which is sufficient.

A height bound alone is insufficient: even a single conversion or
transitivity node may contain an arbitrarily large intermediate term.
The term bound must include all annotations and terms in all premise and
conclusion judgements. Context lengths grow by at most the height along a
branch; for each goal, variables range over its finite context.

Checked boundary and next step
------------------------------

WitnessSearchCheck.seg checks the general extraction theorem with no
object-theory or domain modules in scope: 216 declarations, zero failures.
It is included as a separate session in python3 UNIT/check.py. The frozen
dependencies are unchanged.

The object-theory bounded proof procedure, its finite rule-instance
families, and its completeness proof have not been implemented here.
Consequently the Scott development's Pi-inversion conclusion remains
propositionally truncated. Once that procedure is constructed, instantiate
Procedure.Extract separately at each component judgement and apply it to
the existing mere derivations. The same step applies to mere subject
reduction. This prototype establishes the extraction principle, not those
untruncated object-theory conclusions.
