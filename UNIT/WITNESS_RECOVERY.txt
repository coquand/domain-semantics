Recovering actual derivations from mere existence
================================================

The checked function
--------------------

DerivationRecovery.recover constructs, for every object-theory judgement J,

    || Der(J) || -> Der(J).

The constructor enumeration and its completeness proof supply the search
procedure. There is no additional search assumption. DerivationSearchCheck
checks this construction with no domain model, logical relation, old
adequacy, or earlier Pi-inversion theorem in scope (541 declarations).

IndependentProofRelevant applies it to the mere Pi-inversion conclusion
of IndependentInversion, producing actual component equality derivations.
IndependentSubjectReduction uses that result to prove subject reduction
for the existing head-reduction relations Red1 and Reds. Its syntactic
induction follows the frozen SubjRed proof, with the inversion premise
supplied by the new logical relation. The independent logical-relation
session excludes the original Consequences and SubjRed modules.

Finite constructor closure
--------------------------

The simplest implemented enumeration uses the original constructors as
values. It does not duplicate the object theory's inference rules in a
separate certificate checker.

SyntaxDecision decides equality of raw variables, terms, contexts and
judgements. DerivationSorts uses it to compare these runtime sorts:

    Nat, Fin(n), Tm(n), Ctx(n), Der(n,J).

ConstructorEnumeration represents a partially applied dependent function
by its remaining argument telescope and its actual value. An application
checks the argument's runtime sort and, when it matches, applies that
function. The result contains the original typed value. A derivation
value is therefore already an inhabitant of Der(n,J). Object-theory
conversion is represented by its explicit derivation constructor;
comparison of runtime sorts does not decide object-theory convertibility.

DerivationSignature registers the constructors for natural numbers,
variables, terms, contexts and all 17 derivation rules. Their values are
the existing Syntax constructors. Let E(0) be this finite list, and let

    E(n+1) = E(n) plus all accepted applications of two members of E(n).

Each stage is a finite list. A known member remains present at every
later successor stage. Two given stages can be raised to a common stage,
so any two enumerated values can be applied there.

DerivationEnumeration proves, by induction, that every natural, variable,
term and context occurs. Its induction on Der then proves that every
actual derivation occurs: the rule constructor is already a constant,
and the induction hypotheses provide its premise derivations. Applying
that constructor to its parameters and premises assembles the original
value. No equality decision on derivations or partially applied functions
is required.

ConstructorWitnessSearch scans a finite stage for a value of the requested
sort. Its output has type

    run(n,J) : Der(J) + 1.

An actual derivation supplies a stage at which the scan succeeds. This is
the closed object-theory instance needed by the general extraction theorem.
Finite stages may be very large; this route prioritizes a short correctness
and completeness proof over efficient proof search.

Why truncation elimination is legitimate
---------------------------------------

The general interface Procedure.Bounded in BoundedWitnessSearch has fields

    run      : Nat -> A + 1
    complete : A -> || sum n, Succeeds (run n) ||.

Succeeds (inl a) = Top and Succeeds (inr tt) = Empty. The second outcome
only reports failure to find a witness at that stage. No equality decision,
sethood, or encoding of A is assumed. The procedure need not recover the
supplied witness or return coherent values at different stages.

Let P(n) be the success proposition. The type

    sum n, P(n) * Before(n,P)

of least successful stages is a proposition. The finite failure prefix is

    Before(0,P)     = Top
    Before(n+1,P)   = not P(0) * Before(n, k |-> P(k+1)).

Two least stages agree: a successful zero test contradicts a nonempty
failure prefix; at successors remove the first failed tests and apply
induction. All the remaining fields are propositions.

An actual success at n bounds a finite search through 0,...,n. Its negative
outcome contradicts that success. Both mere existence of a successful
stage and mere existence of A can therefore be eliminated into the
proposition of least successful stages. Finally read the successful value
at the chosen stage. This defines Procedure.Extract.recover : ||A|| -> A.

The selected stage is canonical relative to run. The returned derivation
need not be the one originally used to prove inhabitation. All truncation
eliminations still have proposition-valued targets; no choice axiom is used.

Checks
------

python3 UNIT/check.py runs eight sessions and verifies the 40 frozen hashes.
WitnessSearchCheck checks the general principle (216 declarations).
DerivationSearchCheck checks its complete constructor-enumeration instance
(541), including executable acceptance/rejection checks and success for
the empty-context judgement at the initial stage.
